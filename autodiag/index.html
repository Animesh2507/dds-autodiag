Connect to a live collector

On the peer: AUTODIAG_AGENT_TOKEN=<secret> AUTODIAG_UI_TOKEN=<secret2> AUTODIAG_ALLOWED_HOSTS=<private-ip> dds-autodiag serve --host 0.0.0.0 --port 8081, then enter http://<private-ip>:8081. With an SSH tunnel (ssh -L 8081:127.0.0.1:8081 robot) the peer can stay on 127.0.0.1 (AUTODIAG_AGENT_TOKEN=<secret> dds-autodiag serve --port 8081) and you enter http://127.0.0.1:8081.

What these checks can and cannot establish

Supported

  • Configuration mismatches (domain, discovery range, RMW, distro, DDS XML)
  • Advertised QoS incompatibilities
  • Local shared-memory prerequisites and IPC namespaces

Not verified

  • Which DDS transport was actually selected
  • Packet-level reachability between hosts
  • Vendor-level shared-memory data delivery

No findings does not mean the transport is healthy.

AI providers

Local Ollama works offline and needs no key. Link an API key to use Claude, ChatGPT, Gemini or any OpenAI-compatible service (Groq, OpenRouter, Mistral, LM Studio…). Keys are stored only on this server, in a file only your user can read, and are never shown again. Cloud providers receive only the finding codes and summaries, your question and documentation excerpts — never snapshots, hostnames or IP addresses.

Security

  • All checks are read-only; nothing is restarted or reconfigured.
  • Keep the dashboard on 127.0.0.1. To reach it from another PC, use an SSH tunnel or set AUTODIAG_UI_TOKEN.
  • Snapshots contain hostnames, IPs and paths. Use “Export snapshot” with redaction before sharing.
  • Docker access is privileged; the dashboard only runs docker ps.
